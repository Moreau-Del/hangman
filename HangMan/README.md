# HangMan

## Описание

Проект представляет собой чат-бота с игрой «Виселица», 
рассчитанную на взаимодействие с несколькими пользователями. 
В основе лежит классическая логика игры, дополненная 
авторскими игровыми механиками и возможностями.

## Правила игры

Игроку загадывается слово. Он может по очереди называть 
отдельные буквы или попытаться угадать слово целиком.

- правильная буква открывает все её вхождения;
- неправильная буква добавляет одну ошибку;
- повторная буква не тратит попытку;
- правильное слово сразу приносит победу;
- неправильное слово добавляет одну ошибку;
- при открытии всех букв игрок побеждает;
- после 6 ошибок игрок проигрывает.

## Архитектура

Логика игры отделена от обработки сообщений пользователя и 
от конкретного интерфейса взаимодействия.

### Main

`Main` является точкой входа в приложение и отвечает за создание 
и связывание основных компонентов проекта.

При запуске приложения `Main`:

1. создаёт `WordRepository`;
2. получает из него случайное слово;
3. создаёт `HangmanGame` с выбранным словом;
4. создаёт `Dialogue`, связанный с этой игровой партией;
5. создаёт `Console`, связанный с диалогом;
6. запускает игровой цикл через `Console`.

Таким образом, `Main` не содержит игровой логики и не обрабатывает 
сообщения пользователя. Его задача — **собрать необходимые 
компоненты и установить связи между ними перед запуском приложения**.

#### Связи с другими классами

```
Main
- WordRepository → случайное слово
- HangmanGame ← загаданное слово
- Dialogue ← HangmanGame
- Console ← Dialogue
```

### HangmanGame

`HangmanGame` отвечает за состояние и правила одной игровой партии. 
Класс хранит загаданное слово, использованные буквы, количество ошибок 
и текущее состояние игры.

При создании объект получает загаданное слово. 
Далее он обрабатывает действия игрока:

- `guessLetter()` — попытка угадать букву;
- `guessWord()` — попытка угадать слово целиком.

В зависимости от результата попытки `HangmanGame` изменяет 
состояние игры и возвращает `GuessResult`.

Класс также предоставляет информацию о текущем состоянии игры:

- замаскированное слово;
- загаданное слово;
- количество ошибок;
- состояние игры.

#### Связи с другими классами

- `WordRepository` предоставляет слово при создании игровой партии. 
`HangmanGame` не зависит от способа получения этого слова.
- `Dialogue` передаёт `HangmanGame` действия пользователя и получает результат 
попытки и текущее состояние игры.
- `HangmanGame` не взаимодействует напрямую с `Console` и не занимается 
вводом или выводом.

Таким образом, `HangmanGame` является независимым ядром игровой логики 
и не зависит от способа взаимодействия с пользователем.


### Console

`Console` отвечает за взаимодействие с пользователем через консоль. 
Он получает текстовый ввод, передаёт его в `Dialogue` и выводит 
полученные от него ответы.

При создании `Console` получает объект `Dialogue`, 
с которым будет взаимодействовать.

Основные задачи класса:

- создание `Scanner` для чтения пользовательского ввода;
- запуск игрового цикла через `startGame()`;
- получение сообщений пользователя;
- передача сообщений в `Dialogue`;
- вывод ответов `Dialogue` в консоль;
- завершение игрового цикла после окончания игры.

`Console` не содержит игровой логики и не обрабатывает смысл 
пользовательского ввода, а явялется интерфейсным слоем для пользователя. 
Его можно заменить другим способом взаимодейсвтия с пользователем.

#### Связи с другими классами

```
Console –– сообщение пользователя ––>
Dialogue –– ответ ––> Console
```

### Dialogue

`Dialogue` отвечает за логику взаимодействия пользователя с игрой. 
Он связывает текстовые сообщения пользователя с игровой логикой 
`HangmanGame` и формирует текстовые ответы для интерфейса.

При создании `Dialogue` получает объект `HangmanGame`, 
представляющий конкретную игровую партию.

Основные задачи класса:

- запуск диалога и формирование начального сообщения;
- обработка входящих сообщений пользователя;
- нормализация и проверка пользовательского ввода;
- определение типа ввода: буква, слово или некорректный ввод;
- передача корректных действий в `HangmanGame`;
- преобразование `GuessResult` в понятное пользователю сообщение;
- формирование отображения текущего состояния игры;
- определение, продолжается ли игра.

`Dialogue` не занимается непосредственным вводом и выводом данных. 
Он получает готовую строку сообщения и возвращает готовую строку ответа.

#### Связи с другими классами

- `Console` передаёт `Dialogue` сообщения пользователя и получает от него 
готовые ответы для вывода.
- `Dialogue` передаёт корректные действия пользователя в `HangmanGame`.
- `HangmanGame` возвращает `GuessResult` и предоставляет информацию 
о текущем состоянии игры.
- `Dialogue` использует `UserInput` и `InputType` для представления 
и классификации пользовательского ввода.

Таким образом, `Dialogue` выступает посредником между интерфейсом 
пользователя и игровой логикой, не привязываясь к конкретному 
способу ввода и вывода.


### GameState

`GameState` — перечисление, описывающее текущее состояние игровой партии.

Содержит три возможных состояния:

- `IN_PROGRESS` — игра продолжается;
- `WON` — игрок победил;
- `LOST` — игрок проиграл.

`GameState` используется в `HangmanGame` для хранения текущего 
состояния игры и в `Dialogue` для определения того, продолжается ли 
игра и какую информацию необходимо показать пользователю.


### GuessResult

`GuessResult` — перечисление, описывающее результат отдельной 
попытки пользователя.

Содержит следующие варианты:

- `CORRECT` — буква угадана правильно;
- `INCORRECT` — попытка оказалась неправильной;
- `ALREADY_USED` — указанная буква уже использовалась;
- `WON` — попытка привела к победе;
- `LOST` — попытка привела к поражению.

`GuessResult` формируется в `HangmanGame` после обработки попытки 
и передаётся в `Dialogue`, где на его основе формируется сообщение 
для пользователя.

Таким образом, `GuessResult` **описывает результат конкретного действия**, 
в отличие от `GameState`, который описывает **текущее состояние всей игры**.


### InputType

`InputType` — перечисление, описывающее тип пользовательского ввода 
после его проверки.

Содержит три варианта:

- `LETTER` — пользователь ввёл одну букву;
- `WORD` — пользователь ввёл слово;
- `INVALID` — ввод не соответствует допустимому формату.

`InputType` используется в `Dialogue` при обработке сообщения пользователя. 
На основании типа ввода `Dialogue` определяет, какое действие необходимо 
передать в `HangmanGame`.

Таким образом, `InputType` позволяет отделить **определение типа 
пользовательского ввода** от игровой логики.


### UserInput

`UserInput` — record, представляющий обработанное пользовательское сообщение.

Содержит два значения:

- `value` — нормализованное значение пользовательского ввода;
- `type` — тип ввода, определённый с помощью `InputType`.

`UserInput` создаётся в `Dialogue` после нормализации и проверки 
входного сообщения. Затем его данные используются для определения 
дальнейшего действия: передачи буквы или слова в `HangmanGame` 
либо формирования сообщения об ошибке.

Таким образом, `UserInput` объединяет **значение пользовательского 
ввода и результат его классификации** в один объект.


### WordRepository

`WordRepository` отвечает за хранение и получение слов, используемых для 
создания новых игровых партий.

При создании объект загружает список слов из файла `words.txt`, 
расположенного в `resources`. Слова хранятся в памяти, после чего 
репозиторий может выбрать из них случайное слово.

Основная задача класса:

- загрузить слова из `words.txt`;
- хранить загруженный список;
- предоставлять случайное слово через `getRandomWord()`.

#### Связи с другими классами

- `WordRepository` получает данные из файла `words.txt`.
- `Main` запрашивает у `WordRepository` случайное слово.
- Полученное слово передаётся в `HangmanGame` при создании игровой партии.
- `WordRepository` не зависит от `HangmanGame`, `Dialogue` или `Console`.
- 
Таким образом, источник и способ получения слов отделены от игровой логики. 
Источник слов можно изменить, не изменяя `HangmanGame`.
